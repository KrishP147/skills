# Changelog

One line per user-visible change. The top `## ` heading is always the
version in [`.claude-plugin/plugin.json`](.claude-plugin/plugin.json);
`scripts/lint.py` fails when they differ. Bump both together.

## [0.1.0] - 2026-10-15

- `guard-git` is now a fail-closed allowlist for the push/merge surface (#174, absorbs #171): only a plain feature-branch `git push`, `gh pr create`, gh/git reads, `gh api` GET (graphql read queries) and local git pass; other push options/refspecs, `send-pack`, `git subtree push`, `gh pr merge/close/revert`, `gh alias set`, unknown gh commands, non-GET GitHub API calls, `function f {}` wrappers, `bash <(…)`, `script -c`, `xargs … sh -c`, `deno eval`, PowerShell `(expr)` arguments and `[Diagnostics.Process]::Start` block; docs recommend GitHub branch protection as the backstop. `spend-guard` defaults add `aws ec2 start-instances`, `gcloud compute instances start` and `modal run`, allow GraphQL `saveTemplate`, and block Node/Bun/Deno `runpod-sdk` `.run`/`.runSync`/`.runAsync` one-liners (#178).
- `spend-guard` blocks billable calls behind indirection: aliases, functions and variables defined in the command (bash and PowerShell, incl. `& $X`, `@splat`), `Start-Process`/`saps`/`start`, quote/backtick/base64 tricks, REST/GraphQL writes (Runpod REST, serverless `run`, GraphQL deploy/rent/resume mutations, Vultr, EC2/GCE/Azure), SDK one-liners (`python -c "import runpod; runpod.create_pod(..)"`, boto3 `run_instances`), `aws ec2 request-spot-*`, and an unreadable variable call target or verb (`$X create pod`, `runpodctl $VERB`, `xargs runpodctl`) in a command naming a billable program; inline approval never covers these (use the file).
- Fork safety (#166): `kanban/next/BOARD.md` gains a Target repo section (resolve `origin` with `gh repo view "$(git remote get-url origin)"`, `-R`/`--owner`/explicit `repos/<o>/<r>` on every `gh` call, on a fork ask which repo to write to and never write to the parent without a yes naming it); every `gh`-calling skill and agent points at it and its examples carry `-R`; `pair` asks the PR base on a fork; `meta-orchestrator` records `target_repo` in scope.md.
- `guard-git` round 3 (#156): blocks persisted `git config alias.*` writes that push/merge (and expands any alias written earlier in the command), Bash `alias` and PowerShell `Set-Alias`/`New-Alias`, an unreadable `git $a` subcommand, bare pushes in a `--git-dir`/`GIT_DIR`/`GIT_WORK_TREE` repo on a protected (or unreadable) branch, `bash <<< '…'`, non-literal `iex (…)`, `busybox sh -c`, inline `python -c`/`node -e`/`perl -e`/`ruby -e` code that pushes or merges, base64/hex-decoded text fed to a shell or `iex`, and `curl`/`wget`/`iwr`/`irm` writes to GitHub merge, pulls, contents and refs endpoints; Git Bash `cd /c/…` paths now map to `C:\…`, so a feature-branch push after one is allowed.
- `session-bridge` snapshot `red()` also redacts `curl -u user:pw`/`--user`, `mysql -pPW`, GitLab, Stripe, npm, Google OAuth, DigitalOcean, Twilio, SendGrid and Discord tokens, `.npmrc` `_authToken`/`_auth`, and passwords in `postgres://`/`mysql://`/`mongodb+srv://`/`redis://` and `https://`/`ftp://`/`ssh://` URLs (host kept) and `*_PWD`/`*_PASS` env assignments.
- Planning skill fixes from batch-1 testing: `grill-docs` headings are bare `### Q<n>` with a `Topic:` line so register Sources `grills/<file>#q<n>` resolve (lowercase), numbering is per session, slug is the optional second argument, header gains `Register:`; `grill-docs` and `consult-plan` share one decisions-doc rule (AGENTS/CLAUDE > `docs/decisions.md`/ADR > `skilleddocs/decisions.md`), consult-plan rows get a Source format and a rejected idea is a row only; `wayfinder` no longer double-appends rows for grilling tickets, creates `wayfinder:map` and fixes label colours, defines human-task resolution and `divide` hand-off override; `divide` can stop at one piece, defines session-sized, handles free-text targets and says where to commit; `kanban/`, `wayfinder`, `pr-watch` stop with a message on a non-GitHub remote.
- `spend-guard`: an inline approval (`SPEND_GATE_APPROVED=x cmd`, `env SPEND_GATE_APPROVED=x cmd`, PowerShell `$env:SPEND_GATE_APPROVED='x'; cmd`) now covers only one simple command whose program is the call's only billable match (`true && <create>`, `<create>; <create>`, pipes, `&`, newlines, subshells, `$(...)`, backticks, `bash -c` no longer pass); an approval file never covers two billable commands in one call; dotfiles (`.gitkeep`) in `spend-approvals/` no longer count; free Runpod MCP `create-template`/`create-secret`/`create-registry`/`create-delegation` are allowed. `spend-gate` docs: no audit-trail claim for the consumed file, balance step without `get-account` (ask when no free read exists), illustrative price, mention-only tripwire documented.
- Session and board skill fixes from batch-2 testing: a dated handoff is committed only on the default branch (`TRACKING.md` defines `<default>` and extends the pre-push check); skills nested in a group dir no longer link outside it (new lint rule; broken `../../handoff-auto/TRACKING.md` links replaced by prose); `session-handoff` defines complete and handles a board with no In Review option; `handoff-auto` uses a kebab slug and records branch + base/head SHA; `update-progress` picks the newest handoff by mtime across worktrees, verifies from the base SHA and commits the handoff on the default branch; `kanban-setup` is read-only until the yes, previews board actions and links the board to the repo; `next` lists workflow names, shows In Review cards first in Projects mode and names `priority:*`/`size:*`; `sitrep` checks ignored handoffs, uses the default branch for unpushed and covers every repo touched; `teammate-brief` skips risky setup, gates commits via `TRACKING.md`, skips `wayfinder:*`/in-progress tasks and lists `gh` as optional; `progress-report` README matches its sections.
- Verifier fixes for #143/#148: `repo-scrub` post-push saves every stash entry before the reflog expire (which deletes them all) and pops the stash back on the original branch; a `serial` lane can't starve (other lanes stop starting issues once everything queued ahead of it has started)
- `guard-git` closes push bypasses: config overrides that redirect a push (`-c push.default=matching|upstream`, `-c remote.*.push=`/`mirror`, `--config-env`, `GIT_CONFIG_*` env incl. `export`/`$env:`), persisted `git config` writes of those keys (or `branch.*.merge` naming a protected branch, `include.path`) now blocked outright, `git checkout/switch <protected>` (incl. `-t origin/main`, `main --`), `symbolic-ref HEAD` or `branch -m main` earlier in a chain, PowerShell `iex`/`Invoke-Expression`/`Start-Process`/`Invoke-Command`/`icm`/`& {…}`/`. {…}`/`& ("git")`/scriptblocks and `Set-Location`/`pushd`, nested `bash -c` in a PowerShell call (and `pwsh -c` in Bash) read in that shell's own language, `cmd /d /c`, `wsl`, unreadable `eval $c`/`iex $c`/`& $sb`/`.Invoke()` failing closed on a risky command, unquoted Windows backslash paths (now kept for `PowerShell` calls), and `gh api` writes to `repos/*/contents/*` without an explicit, readable, non-protected `branch=` (`-F branch=@file` blocked); a bare push whose current branch can't be read now fails closed; a PowerShell backtick line continuation no longer trips a false positive.
- Hygiene fixes from batch-3 testing: `repo-scrub` resets every local clone after the force-push (plus `<tmp>`, LFS history check, step numbers); `find-me-a-skill` labels uninstalled entries and fixes tier wording; `gap-scan` handles no upstream and unreachable issues; `repo-showcase` runs its quickstart and gates a missing LICENSE; every skill writing `skilleddocs/` points to `TRACKING.md`, which now documents the `pip install .` packaging hazard; `ponytail` README tips.
- `lanes` file sets keep only where a change lands, uncertain-area rule and an unbounded-issue `serial` lane; rotation resume resets `handoff_budget` but not per-run `stop: after N merges`; implementer wording no longer claims it cannot local-merge; verifier states git facts only from its own commands; manager handles Agent tools with no foreground mode (no fabricating, no sleep-poll, notification wakes it).
- `progress-report`: one-pass link rule (headings, code spans, existing links and decimal CI run ids left alone; no `PR #n` double links), `Progress report NNN` header, `.last-reported` is `<NNN> <filename>`, un-ledgered git work is reported as "not in ledger", and the zone prints a UTC offset on Windows.
- `pair`/`meta-orchestrator`: Windows `.venv`/`node_modules` link and teardown commands work from Git Bash and PowerShell; a hard check stops `git worktree remove` while a dep link (dangling included) remains.
- Agents: manager, implementer and verifier honour `decisions=assume` (open `A-n` recorded and reported); planner README lists **Assumptions needed**.
- `meta-orchestrator`: `decisions: ask|assume` (assume = agent picks its recommendation, logs open `A-n` until you confirm; shown in handoffs and `progress-report`) and a `haiku` chores tier for mechanical no-judgment tasks.
- `upstream-sync`: when the PR can't be opened, files an issue linking the `upstream-sync/verbatim` branch; a failed step no longer skips the modified-file issues, and the run fails only after trying every step.
- CI runs `install-skills.sh` and `install-skills.ps1` into fresh temp dirs (ubuntu, plus `.ps1` on windows-latest) and checks skill, agent and marker counts.
- Plugin `homepage` and README site link point at https://www.krishpunjabi.com/skills (canonical host; the apex form redirects).
- `spend-guard` also blocks `runpodctl serverless|sls run`, the `sls` alias for create/update, `pod update` with `--volume-in-gb`/`--container-disk-in-gb`, `model add`, global flags before the noun (`--profile x pod create`), and MCP `update-pod` with storage keys (v2 `disk`, `mounts.persistent`, `templateId`; v1 `volumeInGb`/`containerDiskInGb`). Global-flag prefix parses linearly (a long flag run no longer backtracks exponentially) and also matches `--x=-1`, quoted values, `--`, and hyphenated profile names like `serverless-prod`.
- Install scripts warn (never delete) on installed skill dirs with the marker that are no longer in the repo ("stale skill(s)"); exit code unchanged.
- `session-bridge` snapshot: LAST USER ASK skips reminders, tool results and agent relays (slash commands shown as `/name args`); Agent/Skill/WebFetch actions labelled; secrets redacted before truncation.
- `spend-guard` default patterns also match `.exe`/`.cmd`, quoted and full-path CLI forms (e.g. `& "C:\...\runpodctl.exe" create`).
- `spend-guard` also covers the PowerShell tool (inline `$env:SPEND_GATE_APPROVED='x';` approval) and more Runpod MCP tools (job submits, endpoint updates, pod start).
- `spend-guard` also blocks `runpodctl start`/`pod start`, noun-first creates (`pod|serverless|network-volume create`), `serverless update`, and network-volume resize (`--size` flag or MCP `update-network-volume` body with `size`).
- `score-loop`: borderline check: a candidate that beats the best by more than half the noise margin but not the full margin reruns the best commit now and is kept only if it beats that fresh best median by more than half the margin; the ledger note logs both medians.
- `score-loop`: freeze lead capped for short deadlines (setup refuses if one experiment doesn't fit), noise margin relative to the best, harness must defeat caching, `## Tried` list apart from Next ideas, summary ranks kept commits by relative gain.
