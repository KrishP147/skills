# Changelog

One line per user-visible change. The top `## ` heading is always the
version in [`.claude-plugin/plugin.json`](.claude-plugin/plugin.json);
`scripts/lint.py` fails when they differ. Bump both together.

## [0.1.0] - 2026-10-15

- Session/board fixes from round-3 testing (#182): `handoff`/`handoff-auto` base SHA on the default branch is the upstream (or the parent of the session's first commit), not HEAD; `TRACKING.md` commit mode also covers an `AGENTS.md` handoff folder already tracked on the default branch; `update-progress` fetches first and counts a head on `origin/<default>` or in a merged PR as merged (squash and rebase merges, stale local default, deleted PR branch via `pull/<n>/head`; an erroring check is never merged), locates only untracked handoffs in other worktrees, commits docs + handoff, pushes only on a yes and uses a `docs/` branch when the default is protected (classic or ruleset PR rule; an unclear answer asks); `progress-report` links `PRs #n, #m` as PRs, skips hex inside branch names, links fork issues to the parent when read from it and counts mentions outside code spans; `kanban-setup` skips the handoff folder; `teammate-brief` commits only on the default branch.
- Orchestration fixes from round-2 testing (#170): `pair`/`meta-orchestrator` teardown moves the worktree's dated handoffs into the main checkout's handoff folder first (an untracked one blocked `git worktree remove`, an excluded one was deleted with it, and the verifier never saw it), never `--force`s, stops and reports when remove still refuses; `pair` builds Windows junction paths with `cygpath -wa` and links only when both are absolute (an empty path made `C:\.venv`), and makes a relative `origin` URL absolute before adding a worktree; `ROTATION.md` with `parallel > 1` starts nothing new, lets every in-flight lane merge or park, then hands off with one loop-state line per lane; `planner` briefs one issue per lane whose head isn't in flight; user answers to plan questions go to the decisions register as `D<k>` and are cited so the verifier doesn't re-decide them; `lanes` uses area-label directories only when the issue names no paths, and setup logs the lanes decision as ledger 001; no PR host → setup stops and asks how merges land.
- Planning and scrub fixes from round-2 testing (#167, #176): `consult-plan` baseline reads the register found by the one decisions-doc rule and states comment-vs-new-issue; `grill-docs` puts the transcript in `grills/` beside a tracked register when `skilleddocs/` is untracked (Close warns Sources need it committed) and takes a slug only after a doc path or quoted subject; `wayfinder` Chart reads the baseline and asks to convert or close an existing issue for the effort, keeps assets inline or in a secret gist (never an untracked link), asks before a claimed or blocked named ticket, passes `divide` the decision rows and resolutions, and uses label colours distinct from `status:*`; `divide` commits only the roadmap file, reports branch + SHA, asks push/PR and switches back; `repo-scrub` post-push warns per branch or tag kept as is (old history, secret included, never push) and offers a gated delete of the save folder.
- Session/board fixes from round-2 testing (#169): `sitrep` counts unpushed against `@{u}`/`origin/<branch>`/`origin/<default>` (never the local default; no ref = unknown, not SAFE) and doesn't flag the handoff commit mode holds uncommitted on a task branch; `update-progress` tests the handoff's head (its worktree or a temp one), sets Done/closes and ticks docs only once merged (else In Review + comment), moves the handoff instead of copying it, skips already-processed ones; the `AGENTS.md`/`CLAUDE.md` handoff folder is covered by the exclude, the pre-push check (`TRACKING.md`, `pair`, `manager`) and `update-progress`; `progress-report` keeps bare URLs, links `PR#n`, skips its own commits and says when to commit; `kanban-setup` dedupes every mode against open and closed issues, offers label mode instead of a refresh and has label-mode item steps; `handoff`/`handoff-auto` record branch/base/head and dirty WIP; `next` orders priority within each status group; `teammate-brief` reads in-progress from the board; README notes skill READMEs' links are GitHub-only; `BOARD.md` Target repo detects a fork with issues disabled (#177): says so, reads the parent, writes only after a yes naming the parent or an approved `--enable-issues`.
- Hygiene fixes from round-2 batch-3 testing (#168): `repo-scrub` post-push in-place reset ([`POST-PUSH.md`](repo-scrub/POST-PUSH.md)) stashes the WIP first, saves every stash entry (untracked parts included) and every local-only or unpushed branch and tag outside the repo, re-creates and verifies the stashes on the new history, deletes a branch or tag only on a yes and no longer runs `reflog expire --all` (it wiped the stash list); a blocked force-push hands the user the commands; personal strings from `repo-showcase` get a `git log -S` check, a `literal:` replace rule and a verify; the findings table prints `-` for a large blob's commits. `repo-showcase` runs its quickstart from a clean clone into a temp prefix or venv, never globally and never by registry name unless the entry's repository URL is this repo; accepts a license declared in `package.json`/`pyproject.toml`. `find-me-a-skill` checks `~/.claude/skills/<name>/` and the plugin before calling a skill not installed.
- `spend-guard` blocks billable calls behind indirection: aliases, functions and variables defined in the command (bash and PowerShell, incl. `& $X`, `@splat`), `Start-Process`/`saps`/`start`, quote/backtick/base64 tricks, REST/GraphQL writes (Runpod REST, serverless `run`, GraphQL deploy/rent/resume mutations, Vultr, EC2/GCE/Azure), SDK one-liners (`python -c "import runpod; runpod.create_pod(..)"`, boto3 `run_instances`), `aws ec2 request-spot-*`, and an unreadable variable call target or verb (`$X create pod`, `runpodctl $VERB`, `xargs runpodctl`) in a command naming a billable program; inline approval never covers these (use the file).
- Fork safety (#166): `kanban/next/BOARD.md` gains a Target repo section (resolve `origin` with `gh repo view "$(git remote get-url origin)"`, `-R`/`--owner`/explicit `repos/<o>/<r>` on every `gh` call, on a fork ask which repo to write to and never write to the parent without a yes naming it); every `gh`-calling skill and agent points at it and its examples carry `-R`; `pair` asks the PR base on a fork; `meta-orchestrator` records `target_repo` in scope.md.
- `guard-git` round 3 (#156): blocks persisted `git config alias.*` writes that push/merge (and expands any alias written earlier in the command), Bash `alias` and PowerShell `Set-Alias`/`New-Alias`, an unreadable `git $a` subcommand, bare pushes in a `--git-dir`/`GIT_DIR`/`GIT_WORK_TREE` repo on a protected (or unreadable) branch, `bash <<< '…'`, non-literal `iex (…)`, `busybox sh -c`, inline `python -c`/`node -e`/`perl -e`/`ruby -e` code that pushes or merges, base64/hex-decoded text fed to a shell or `iex`, and `curl`/`wget`/`iwr`/`irm` writes to GitHub merge, pulls, contents and refs endpoints; Git Bash `cd /c/…` paths now map to `C:\…`, so a feature-branch push after one is allowed.
- `session-bridge` snapshot `red()` also redacts `curl -u user:pw`/`--user`, `mysql -pPW`, GitLab, Stripe, npm, Google OAuth, DigitalOcean, Twilio, SendGrid and Discord tokens, `.npmrc` `_authToken`/`_auth`, and passwords in `postgres://`/`mysql://`/`mongodb+srv://`/`redis://` and `https://`/`ftp://`/`ssh://` URLs (host kept) and `*_PWD`/`*_PASS` env assignments.
- Planning skill fixes from batch-1 testing: `grill-docs` headings are bare `### Q<n>` with a `Topic:` line so register Sources `grills/<file>#q<n>` resolve (lowercase), numbering is per session, slug is the optional second argument, header gains `Register:`; `grill-docs` and `consult-plan` share one decisions-doc rule (AGENTS/CLAUDE > `docs/decisions.md`/ADR > `skilleddocs/decisions.md`), consult-plan rows get a Source format and a rejected idea is a row only; `wayfinder` no longer double-appends rows for grilling tickets, creates `wayfinder:map` and fixes label colours, defines human-task resolution and `divide` hand-off override; `divide` can stop at one piece, defines session-sized, handles free-text targets and says where to commit; `kanban/`, `wayfinder`, `pr-watch` stop with a message on a non-GitHub remote.
- `spend-guard`: an inline approval (`SPEND_GATE_APPROVED=x cmd`, `env SPEND_GATE_APPROVED=x cmd`, PowerShell `$env:SPEND_GATE_APPROVED='x'; cmd`) now covers only one simple command whose program is the call's only billable match (`true && <create>`, `<create>; <create>`, pipes, `&`, newlines, subshells, `$(...)`, backticks, `bash -c` no longer pass); an approval file never covers two billable commands in one call; dotfiles (`.gitkeep`) in `spend-approvals/` no longer count; free Runpod MCP `create-template`/`create-secret`/`create-registry`/`create-delegation` are allowed. `spend-gate` docs: no audit-trail claim for the consumed file, balance step without `get-account` (ask when no free read exists), illustrative price, mention-only tripwire documented.
- Session and board skill fixes from batch-2 testing: a dated handoff is committed only on the default branch (`TRACKING.md` defines `<default>` and extends the pre-push check); skills nested in a group dir no longer link outside it (new lint rule; broken `../../handoff-auto/TRACKING.md` links replaced by prose); `session-handoff` defines complete and handles a board with no In Review option; `handoff-auto` uses a kebab slug and records branch + base/head SHA; `update-progress` picks the newest handoff by mtime across worktrees, verifies from the base SHA and commits the handoff on the default branch; `kanban-setup` is read-only until the yes, previews board actions and links the board to the repo; `next` lists workflow names, shows In Review cards first in Projects mode and names `priority:*`/`size:*`; `sitrep` checks ignored handoffs, uses the default branch for unpushed and covers every repo touched; `teammate-brief` skips risky setup, gates commits via `TRACKING.md`, skips `wayfinder:*`/in-progress tasks and lists `gh` as optional; `progress-report` README matches its sections.
- Verifier fixes for #143/#148: `repo-scrub` post-push saves every stash entry before the reflog expire (which deletes them all) and pops the stash back on the original branch; a `serial` lane can't starve (other lanes stop starting issues once everything queued ahead of it has started)
