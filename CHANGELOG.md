One line per user-visible change. The top `## ` heading is always the
version in [`.claude-plugin/plugin.json`](.claude-plugin/plugin.json);

## [0.1.0] - 2026-10-15

- Workflows `unattended-backlog`, `climb-a-score` and `safe-to-close` gain `/switch` and `/remind` steps for usage limits (#235).
- Skills split into categories (#227): Plan and decide, Build and orchestrate, Sessions and accounts, Review and report, Repo and safety, Kanban board, plus agents and hooks. One list in `site/data/meta.json` (`categories`, was `map_groups`) drives the site home, `/map`, each page's tag and the README "What's here" tables; a test fails if they drift.
- skill pages: more spacing, bullets
- New `remind` skill (#226): `/remind when <account>'s session|weekly limit resets`, `when <account> is under N%`, `in 2h ...`, `at 3pm ...`, `list`, `cancel <id>`. Reset times come from `switch`'s usage cache (unknown account, no cache or an already-reset window is an error, never a guess). Due reminders show once at the next prompt on any account through `switch`'s hook (a one-line hook without switch); timed ones also get a one-shot desktop notification (Windows scheduled task with a PowerShell toast, `msg` fallback; `at` on macOS/Linux). `reminders.json` sits next to the switch registry (`~/.claude-remind/` without it).
- `switch` statusline and hook in every account (#219): `setup` and `setup --uninstall` write and remove them in each distinct account `settings.json` (a symlinked or hardlinked one once, a missing dir skipped, a non-JSON file warned about and left alone) after one diff and `[y/N]`; each file's own statusline is recorded and restored (the old one-file registry entry carries over). `add` and `migrate` do the same for a new account with its own `settings.json`, and `remove` takes them out of a file no other account uses, so `/switch` from any account goes through the hook without an API call.
- `switch` simpler: the pre-switch notes keep only what ends or pauses (subagents, background commands, Remote Control); artifacts, routines, connectors and the Chrome extension are in the README only. A subagent counts as running only while its last record isn't a final reply (no 10-minute window). `/switch <name> <more words>` (other than a trailing `yes`) prints `usage: /switch [name]` and switches nothing.
- `install-skills --workflow <name>` / `-Workflow <name>` (#222) installs one sample workflow's skills, agents and hooks plus their dependencies (agent preloads, skills a skill calls or links into, `guard-git` with any agent); `--list-workflows` / `-ListWorkflows` lists them. Workflow hooks are copied and their settings snippet printed, never wired. A partial install touches and warns about nothing outside the selection; the full install is unchanged. Each workflow on the site shows its one-line install command, and every agent and hook must now be in a workflow too.
- `switch` account-bound features (#214, part 3): `/switch` prints a pre-switch check (running subagents and Remote Control are live; background Bash and monitors die; artifacts and routines stay on the old account; connectors/MCP OAuth and the Chrome extension follow the login) and, with three or more accounts, asks a yes when something is live (two accounts never ask): the hook switches on the same `/switch [name]` again within 120 s or `/switch [name] yes`, no model call. A Remote Control session relaunches with `--remote-control` under the target (`/switch rc-ok <name> on` stops the question). The target resumes by the transcript's absolute path when its `projects/` doesn't hold the session. Each switch writes a resume note (cwd, branch, last commit, live subagent ids) whose path the launcher prints. README section "What follows the account".
- `switch` account-bound features (#214, part 3; simplified in #221): before each switch `/switch` prints notes and never asks: running subagents pause (resume each with `SendMessage` to its id), background Bash and monitors die, artifacts and routines stay on the old account, connectors/MCP OAuth and the Chrome extension follow the login, and with Remote Control on, a line that it ends with the session (run `/remote-control` on the target if wanted). A trailing `yes` (`/switch work yes`) is ignored. The target resumes by the transcript's absolute path when its `projects/` doesn't hold the session. Each switch writes a resume note (cwd, branch, last commit, live subagent ids) whose path the launcher prints. README section "What follows the account".

- `switch` account management (#211, part 2): `add <name>` makes a config dir that links the first account's skills, agents, commands, plugins, projects, settings.json and CLAUDE.md (junctions/symlinks; hardlink or copy with a warning without symlink rights), regenerates the shell files setup recorded and moves a launched session into it; `remove` shows a dry-run plan and, with `--delete-dir` and a yes, unlinks every link before deleting and never recurses through one; `rename`, `list` and a read-only `migrate` of existing `~/.claude-*` dirs. Setup also adds a statusline to the shared settings.json (account in its colour, session and weekly used % with time left; a statusline you had is wrapped, run with the same input, and restored by `setup --uninstall`) and a `UserPromptSubmit` hook that warns once at 90% and 97% naming the account with the most room, and catches a typed `/switch [name]` so it switches without an API call, even at 100%. `theme <name> <theme>` gives an account its own theme via a `--settings` overlay (merged with yours); the launcher sets the tab title and picks up a rename of the current account.
- New `switch` skill (#210, part 1): several Claude accounts, one `CLAUDE_CONFIG_DIR` each, in `~/.claude-switch/accounts.json`; `claude` opens the most recently used, `claude-<name>` a named one; `/switch [name]` resumes the conversation on the previous or named account (`--continue` when `--resume` fails). One stdlib launcher per terminal watches only its own request file, so concurrent sessions never cross; `setup` writes bash, zsh, fish, PowerShell 5.1 + 7 and cmd wrappers after a diff and a yes.
