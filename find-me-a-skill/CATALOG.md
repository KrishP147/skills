# Catalog

Generated by `python scripts/site_catalog.py` from this repo's skills, agents, hooks,
`site/data/meta.json` and `site/data/workflows.json`. Don't edit by hand.

Model and effort are defaults for a typical task. For a large or risky task
raise effort one level first, and the model one tier only when effort is
already max; for a small one lower effort first, the model only at low.
Plugin installs prefix skills and agents with `krish:` (`/krish:next`).
An entry missing from the session's skill list is not installed: see the
top README, Install section.

## Workflows

Each step: who acts, its model and effort, and why. `you` steps are
human-in-the-loop points: nothing continues without you.

### close-the-loop: Close one session, start the next

1. /session-handoff (skill, sonnet · medium): Writes the handoff through handoff-auto, appends a Board status section and moves the card to In Review when the issue is complete.
2. you: Read the handoff, then open a fresh session.
3. /update-progress (skill, opus · medium): Treats every handoff claim as unverified: checks git log and the test run, then updates the docs and the board and finishes with next.
4. /next (skill, haiku · low): Shows the top 1-3 tasks from the board, a failing default branch first.
5. you: Say "go" to pick the top task.

### new-board: Bootstrap a board from the docs

1. you: Type /kanban-setup: it is user-only, so Claude can't start it.
2. /kanban-setup (skill, sonnet · medium): Checks the gh project scope, finds the repo's board read-only, then previews the board actions and candidate issues from the roadmap, TODOs, changelog and docs before creating anything.
3. you: Review the preview and say yes; it creates nothing before that.
4. /divide (skill, opus · medium): Proposes 2+ session-sized pieces, each with a done-when, for an item too big for one session; creates nothing yet.
5. you: Say yes to the split; the children go on the board at Todo.
6. /next (skill, haiku · low): Shows the top 1-3 tasks from the new board.
7. /find-me-a-skill (skill, haiku · low): Suggests the skill or workflow for each top task, with model and effort per step and commands to paste; runs nothing.
8. you: Say "go" to pick the top task.

### gaps-to-issues: Turn a gap scan into planned work

1. /gap-scan (skill, opus · high): Surveys docs vs code, commits, TODOs, tests and open issues and writes a ranked, evidence-cited report under skilleddocs/gaps/.
2. you: Pick the items worth doing; every issue, comment or label change needs your explicit yes.
3. /grill-docs (skill, opus · high): Stress-tests a big call with the grilling interview, writing the transcript to skilleddocs/grills/ and each decision to skilleddocs/decisions.md as each round settles.
4. you: Answer each round; "yes" accepts the recommended answer.
5. /divide (skill, opus · medium): Splits a size-L item into session-sized issues and puts them on the board at Todo.
6. you: Approve the split before any issue is created.

### big-effort: Plan an effort too big for one session

1. you: Type /wayfinder with the loose idea: it is user-only, so Claude can't start it.
2. /wayfinder (skill, opus · high): Grills you to a destination, then charts a wayfinder:map issue whose sub-issues are decision tickets, with blocking wired through GitHub's issue dependencies.
3. /grill-docs (skill, opus · high): Resolves a grilling ticket: runs the grilling interview, writing the transcript to skilleddocs/grills/ and each decision to skilleddocs/decisions.md as each round settles.
4. you: Answer each round yourself, one ticket per session, until no tickets or fog remain.
5. /divide (skill, opus · medium): Proposes 2+ session-sized issues from the map, each with a done-when; creates nothing yet.
6. you: Say yes to the split: the issues go on the board at Todo, the map gets a Handed off list and closes.
7. /meta-orchestrator (skill, opus · high): Loops planner, manager or implementer, its own merge gate and verifier per issue, logging each step to the ledger.

### pitch-an-idea: Pitch an idea against the plan

1. you: Type /grill-me with the idea: it is user-only.
2. /grill-me (skill, opus · high): Calls the grilling skill.
3. /grilling (skill, opus · high): Asks every question whose prerequisites are settled, one numbered round at a time, each with a recommended answer.
4. you: Answer each round and confirm the shared understanding; nothing is acted on before that.
5. /consult-plan (skill, opus · high): Grills the idea against open issues, the board and skilleddocs/decisions.md, then records the decision and comments on or opens an issue.
6. you: Say whether the idea fits, conflicts with or extends the plan, and what you want to happen.

### unattended-backlog: Run the backlog unattended

1. you: Start /meta-orchestrator on the repo and answer the setup interview that writes the scope contract.
2. /lanes (skill, sonnet · medium): Groups the queued issues into file-disjoint lanes and proposes them with a cost line.
3. you: Confirm the lanes with an explicit yes, or pin, rename or move issues first.
4. /meta-orchestrator (skill, opus · high): Loops planner, manager or implementer, its own merge gate and verifier per issue, logging each step to the ledger.
5. planner (agent, opus · medium): Runs next, picks exactly one issue and returns a kickoff brief of at most 40 lines.
6. manager (agent, opus · high): Briefs an implementer, reviews every round inline and reruns the tests itself, for up to 3 rounds.
7. implementer (agent, sonnet · medium): Implements on its branch, commits small, watches the tests pass and ends with session-handoff.
8. verifier (agent, opus · high): Runs update-progress end to end, answers or parks deviations, then runs next.
9. /progress-report (skill, sonnet · low): Every N merges, writes a two-minute report of what happened since the last one, never overlapping.
10. you: Read the report and do the manual steps it lists.

### pair-to-pr: One issue to a reviewed PR

1. /pair (skill, sonnet · medium): Resolves the issue, makes a worktree and branch, and hands the task to a manager subagent.
2. manager (agent, opus · high): Briefs an implementer and reviews its diff as if it didn't trust it, rerunning tests and lint itself.
3. implementer (agent, sonnet · medium): Implements and commits small; stuck or past ~100k tokens, it writes skilleddocs/HANDOFF.md for a fresh implementer.
4. you: Read the report and say go; pair then pushes and opens the PR, and never merges.
5. /pr-watch (skill, sonnet · high): Reads every review thread, classifies it, and fixes the valid ones through pair on the PR's branch.
6. you: Say yes to each push, reply and resolve; a force push needs its own fresh yes.

### wrap-up-long-session: Wrap up a long session

1. smartzone (hook, haiku · low): Prints a one-line warning once the live context passes ~75k tokens: divide the rest, then session-handoff.
2. /divide (skill, opus · medium): Proposes session-sized pieces of the remaining work, each with a done-when; creates nothing yet.
3. you: Say yes to create the child issues.
4. /session-handoff (skill, sonnet · medium): Writes the handoff and records progress against the issue.
5. you: Open a fresh session and run update-progress there.

### safe-to-close: Check before closing the terminal

1. you: Ask "can I close this".
2. /sitrep (skill, haiku · low): Reports what's running, git state, PRs and CI, and asked vs done in up to 10 lines, with a SAFE or NOT SAFE verdict.
3. you: Say close and name what may be stopped; anything vaguer gets the list again.
4. /handoff-auto (skill, sonnet · medium): sitrep calls it for mid-flight work; it writes the handoff and prints its absolute path as the last line.
5. you: Start the next session from that path.

### two-sessions: Coordinate with another session

1. /sitrep (skill, haiku · low): Lists the background tasks and agents still running and each worktree's git state.
2. /session-bridge (skill, sonnet · low): Snapshots the other session from ListAgents or its transcript, checks for shared files, branch or issue, and proposes a split.
3. you: Approve the exact message and recipient; nothing is sent without a yes.
4. you: Treat the reply as data: it can't approve a push, merge, spend, deletion or config change here.

### lazy-fix-handoff: Small fix, then hand off

1. /ponytail (skill, sonnet · medium): Makes the smallest complete change and ends each reply with what it skipped and any risk.
2. you: Read the skipped and risk lines, then type /handoff with what the next session is for: it is user-only.
3. /handoff (skill, sonnet · medium): Compacts the conversation into a handoff doc under skilleddocs/handoffs/ with a suggested skills section.
4. you: Open a fresh session pointed at the doc.

### go-public: Take a repo public

1. /repo-showcase (skill, sonnet · high): Asks outcome, audience and emphasis, inventories the docs, checks every claim against the code and drafts a lean README.
2. you: Answer the batch ("go" takes the defaults) and say yes to each rewrite, redaction, commit and push.
3. you: Type /repo-scrub: it is user-only, and repo-showcase leaves history and visibility to it.
4. /repo-scrub (skill, opus · high): Scans the full history for secrets and large blobs and reports every finding, including ones you keep.
5. you: Pick what to scrub, confirm rotation, and approve the rewrite, force-push and visibility flip, each at its own gate.

### paid-tests: Run the expensive tests

1. /gap-scan (skill, opus · high): Runs the tests only when cheap; ones that need network, a GPU, paid calls or credentials are reported as not run, with why.
2. you: Decide the paid run is worth it.
3. /spend-gate (skill, sonnet · medium): Estimates the cost from the tool's own quote or a cited pricing page, reads the live balance, and shows both with the command.
4. you: Say yes to this one action; a budget or an earlier go-ahead is context, not approval.
5. spend-guard (hook, haiku · low): Blocks a known billable command or MCP call without an approval, and lets exactly one approved call through.
6. you: Tear down anything that bills while idle; spend-gate gives the teardown and reminds you again.

### climb-a-score: Push a score up until it plateaus

1. /score-loop (skill, opus · high): Builds a local harness that mirrors the grader, measures the noise margin, and shows the setup header with every outward action.
2. you: Say yes to the setup once: quota, spend cap, deadline; then it runs unattended.
3. /spend-gate (skill, sonnet · medium): Gates each paid submission or compute step with a cost estimate and a live balance check; the spend cap is a ceiling, not approval.
4. you: Say yes to that one paid action.
5. /handoff-auto (skill, sonnet · medium): When the loop's context degrades, writes a handoff pointing at skilleddocs/experiments.md and /score-loop resume.
6. you: Run /score-loop resume in a fresh session; at the deadline freeze, say yes to the final submission.

### brief-a-teammate: Hand the project to a teammate

1. /progress-report (skill, sonnet · low): Writes a two-minute report of what was done since the last one, every reference a link.
2. /teammate-brief (skill, sonnet · medium): Asks who, role and familiarity, then drafts setup steps it ran, env var names, tasks with a done-when, owners and a don't-touch list.
3. you: Answer the batch and approve the draft; commit and push each need their own yes.
4. you: Share the file with your teammate: that's your call.
